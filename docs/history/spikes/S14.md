# S14: Can Crucible observe current subscription quota state per harness, and use it for routing and for a wait-and-resume strategy?

Run 2026-09-17, 10:25 to 11:00 CDT, on the reference workstation, against
`quota-axi` 0.1.46 installed into a scratch prefix (never globally) and
pointed at Crucible's dedicated credential directories as they stand on
this host, one per harness under a single private root (spec 12's
`credentials.<harness>.path`; `<CRED_ROOT>` below). No task was run and no
model was called; this spike reads quota state only.

Decision: **adjust design, and proceed with conditions.** quota-axi answers
the question for two of the three harnesses today, from the dedicated
directories only, without spending model quota and without touching the
operator's daily-use state, and it degrades honestly to "unknown" rather
than to a fabricated number. Claude Code is the gap: Crucible's dedicated
Claude credential is the `setup-token` long-lived token S1b recorded, and
the tool's two paths to it both fail (no `.credentials.json` for the
file path, 403 from the usage endpoint for the environment-variable path).
The design adjustments this forces are that the signal must be advisory
only, that a quota deferral cannot reuse the concurrency-cap deferral
because that one holds a checkout lease, and that AGY's reading requires a
harness CLI inside the service container, which may cost more than the
reading is worth. A wait-and-resume strategy is supportable for Codex and
AGY, where a real reset timestamp exists, and not for Claude Code.

## Method

Everything ran on the host as the operator's uid, not in a container.

```sh
# Pinned, local, reproducible. Nothing installed globally.
npm install --prefix <scratch>/qaxi --no-save --ignore-scripts quota-axi@0.1.46

# Every invocation used this sanitized environment: an empty scratch HOME and
# scratch XDG roots, so any default-location lookup lands in the scratch tree.
env -i PATH="<node-bin-dir>:<user-bin>:/usr/bin:/bin" \
    HOME=<scratch>/qhome \
    XDG_CONFIG_HOME=<scratch>/qhome/.config XDG_CACHE_HOME=<scratch>/qhome/.cache \
    XDG_DATA_HOME=<scratch>/qhome/.local/share XDG_STATE_HOME=<scratch>/qhome/.local/state \
    TERM=dumb NO_COLOR=1 <cmd>

# The three per-harness readings.
CODEX_HOME=<CRED_ROOT>/codex        quota-axi --provider codex  --profile-only [--json]
CLAUDE_CONFIG_DIR=<CRED_ROOT>/claude_code quota-axi --provider claude --profile-only [--json]
HOME=<CRED_ROOT>/agy                quota-axi --provider agy [--json]     # XDG roots still scratch

# The isolation watch: read-only, placed on the operator's own daily-use files.
inotifywait -m -r --timefmt '%H:%M:%S' --format '%T %e %w%f' \
  -e access -e open -e modify -e close \
  ~/.codex/auth.json ~/.gemini/antigravity-cli/antigravity-oauth-token ~/.cache/quota-axi/
```

The decoy runs in "Isolation" below use the same sanitized environment with
`HOME` at a scratch directory seeded with a `.codex/auth.json` and a
`.claude/.credentials.json` holding one non-secret marker object each.

The firstmate facts cited below were established by reading that
repository's own files, not by report: `bin/fm-quota-axi-lib.sh` for the
0.1.29 version floor and the jq validator asserting `schemaVersion == 5`,
`bin/fm-procevent-quota.sh` for the 60 second watcher interval,
`.agents/skills/quota-array-dispatch/SKILL.md` for the rule never to read a
reset as a deadline, and `docs/verification/dispatch-auth.md`, whose own
verification dates are 2026-07-30 and 2026-08-18, for the recorded field
shapes.

### Conventions and deviations in this record

- Every captured line is redacted: account identifiers, emails, tokens, and
  absolute paths outside the dedicated credential root are replaced with
  placeholders. No credential value is recorded anywhere.
- The operator's own directories are named in tilde-relative form
  (`~/.codex/auth.json`). That form carries no user name and no identity,
  and naming the file that was watched is the point of the evidence.
- `--full` was run three times, to establish the provenance fields and to
  learn what the mode exposes. Its `account` object holds `accountId` and
  `email`; those values were not recorded here, the field names are, and
  the raw captures were shredded at the end of the spike. Default `--json`
  and default TOON carry no account object at all, which is why the
  integration shape below forbids `--full` outright.
- Spec 21 says credentials used during spikes are the operator's own
  directories copied to a scratch location. This spike deliberately did not
  do that. It ran against the live dedicated directories, because copying a
  credential is the failure mode the whole exercise exists to avoid, and
  because the question is specifically whether the tool can be aimed at
  those directories. Every dedicated auth file's size, modification time,
  and hash was recorded before and after, and none changed.

## Isolation from the operator's daily-use directories

This was the blocking constraint. It holds, and the evidence now separates
the two mechanisms that could be responsible.

The tool's `--profile-only` mode exists for this problem. It takes one
`--provider`, supports Claude and Codex only, requires an explicit non-blank
`CLAUDE_CONFIG_DIR` or `CODEX_HOME`, and documents that it has no
default-location fallback, reads no keychain, invokes no CLI fallback,
delegates no credential refresh, and neither reads nor writes its own quota
cache. AGY has no `--profile-only`; it is isolated by `HOME` instead, which
is the lever S1b already used for AGY's dedicated login.

### The decoy runs: the mode, not just the scoped HOME

Every other run in this spike used a scratch `HOME`, which on its own would
prevent a fallback to `~/.codex` whether or not the mode does. To separate
them, a scratch `HOME` was seeded with a decoy `.codex/auth.json` and
`.claude/.credentials.json` (valid JSON, one non-secret marker field each)
and the runs repeated. If the mode has a fallback, the decoy is what it
falls back to, and the decoy is loud.

| Run | Invocation | Result |
|---|---|---|
| A | `--profile-only`, `CODEX_HOME` at the dedicated directory, decoy present in `HOME` | returned the **dedicated** account's real reading (`codex,all_models,2,...`). The decoy was not consulted. |
| B | same, but no `--profile-only` and no `CODEX_HOME` | `quota[0]`, `attention: codex,all,error,Codex quota unavailable`. It found and used the decoy. |
| C | `auth --json` for run B | `{"source":"auth-json","path":"<SCRATCH>/decoyhome/.codex/auth.json","status":"invalid"}` |
| D | `--profile-only`, `CLAUDE_CONFIG_DIR` at the dedicated directory, decoy present in `HOME` | `oauth-file` path reported as `<CRED_ROOT>/claude_code/.credentials.json`, status `missing`; `attention: claude,all,unavailable,Claude profile credentials missing`. The decoy was not consulted. |
| E | same, but no `CLAUDE_CONFIG_DIR` | `{"source":"oauth-file","path":"<SCRATCH>/decoyhome/.claude/.credentials.json","status":"invalid"}`. It found and used the decoy. |

A and D establish that `--profile-only` reads the directory it is given and
nothing else. B, C, and E establish that the fallback being avoided is real
and would otherwise fire: without the mode and the variable, the tool goes
straight to `$HOME`. The mode is therefore load-bearing on its own, and the
scoped `HOME` is defence in depth rather than the whole guarantee.

### Corroborating evidence

**Its own source reporting.** `quota-axi auth --json`, run scoped, names
every path it would consult:

```json
{ "provider": "codex", "sources": [
    { "source": "auth-json", "path": "<CRED_ROOT>/codex/auth.json", "status": "available" },
    { "source": "pi:openai-codex", "path": "<SCRATCH>/qhome/.pi/agent/auth.json", "status": "missing" },
    { "source": "cli-rpc", "path": "<node-bin-dir>/codex", "status": "available" } ] }
{ "provider": "claude", "sources": [
    { "source": "env", "status": "available" },
    { "source": "oauth-file", "path": "<CRED_ROOT>/claude_code/.credentials.json", "status": "missing" } ] }
{ "provider": "agy", "sources": [
    { "source": "loopback", "status": "missing" } ] }
```

Every credential path named is inside the dedicated root or the scratch
tree. One path is outside both: the Codex `cli-rpc` entry, which is the
Codex CLI **binary**, not credential state, and which `--profile-only`
disables outright. The AGY entry names no path at all, so this evidence
corroborates nothing for AGY; AGY's isolation rests on `HOME` scoping and
on the decoy-run logic, not on this report.

**A filesystem watch with a positive control.** A read-only `inotifywait`
watch was placed on `~/.codex/auth.json`,
`~/.gemini/antigravity-cli/antigravity-oauth-token`, and
`~/.cache/quota-axi/`. Nine quota-axi invocations, three per harness, ran
between 10:27:38 and 10:27:46 CDT and produced **zero** open or access
events on any of them. A deliberate read of the same three files at
10:27:47 CDT fired all six expected events, proving the watch was live. The
eight seconds fit the measured per-call latencies (AGY 1.7 s, Codex 0.5 s,
Claude 0.25 s, run sequentially).

**No write anywhere.** No dedicated auth file changed size, modification
time, or content hash across the whole spike, and neither did any of the
operator's. The only file quota-axi created was its own quota cache, inside
the scratch `XDG_CACHE_HOME`, and `--profile-only` did not even do that.

### What this evidence does not establish

- `~/.claude/.credentials.json` could not be watched usefully: the session
  running this spike is itself Claude Code on the operator's own credential
  and touches that file about once a second, so its events are
  indistinguishable background noise. Runs D and E carry Claude Code
  instead.
- Access-time comparison was abandoned as self-contaminating: the
  fingerprint script's own `sha256sum` updates the access times it is meant
  to measure.
- No run was made with the operator's real `HOME` and `--profile-only`,
  which would be the last confound removed. It was not run because a
  fallback, if one existed, would read the operator's credential, which is
  the outcome the spike is forbidden to risk. The decoy runs answer the
  same question without that risk.
- `strace` is absent on this host and unprivileged user namespaces are
  denied, so neither a syscall trace nor a `bwrap` mount-namespace proof
  was available.

### The mode caveat, which is a design constraint

`--profile-only` accepts exactly one provider, so a single combined call
covering all three harnesses cannot use it. One combined call was measured
(1.9 s for all three, which is about the slowest single provider, so the
tool queries providers concurrently). It stayed inside the dedicated
directories only because `HOME` was scoped as well. Crucible should make
three separate scoped calls, never one, so Claude and Codex keep the mode
whose guarantee is written down and now demonstrated.

The cause is the credential shape, not the tool. S1b established that
Crucible's dedicated Claude Code session is a `setup-token` long-lived
token held in a file and delivered through the CLI's environment variable,
which spec 07 already names as the one exception to file-only delivery.
Anthropic's usage endpoint answers that token with 403. quota-axi treats
403 as insufficient evidence of a sign-out, by its own documented rule, and
reports an error rather than claiming the credential is dead. Whether a
`.credentials.json`-shaped OAuth session would be readable was **not
tested**: the only such file on this host is the operator's own.

## Is a reset time actually available

| Harness | Reset available | Usable as a wait-and-resume deadline |
|---|---|---|
| codex | yes, per bounding window (`weekly`, 2026-09-19 10:57 CDT), plus an independent `projectedExhaustedAt` and `usableRunwaySeconds` | yes for the deferral horizon; **no** as a completion deadline |
| agy | yes, per window, plus the vendor's own reset text; but on a wholly unused window it is "now plus the window length" and moves on every call | yes, only for a window that is actually drawn down |
| claude_code | no reading at all today | no |

firstmate's `quota-array-dispatch` skill forbids comparing `resetsAt`
against a completion horizon as though reset were an exhaustion deadline,
and passes `through_reset` on its feasibility floor precisely because such
a window reaches its refill without exhausting. That rule is correct and
Crucible should inherit it. The right reading is the other direction: a
reset says *when a deferred attempt is worth trying again*, not *how long
the current attempt has*. For "how long do I have", the field is
`usableRunwaySeconds` under `projected_exhaustion`, which Codex supplies
and AGY does not.

Where no reset is available, Crucible does not need one. The behaviour that
does not depend on a reset is: observe the exhausted state, mark the pool
ineligible, defer the attempt before it launches, and re-probe on the
supervisor's existing tick until the reading says otherwise. For Claude
Code, with no reading at all, Crucible keeps exactly today's behaviour,
which is the degradation path the design needs regardless.

## Which reading bounds which pool

Neither the readings nor the pools line up by name, and getting this wrong
is the easiest way to mis-route. 05b's `default-routing` version 2 declares
three pools, each with a `5h` window:

| Pool (05b) | Harness | Observation that bounds it | Window the observation actually describes |
|---|---|---|---|
| `openai-sub` | codex | `codex` / `all_models` | **weekly**, not 5h. The pool's declared `window: "5h"` and the observed bound disagree, and the observation is the tighter and more real of the two. |
| `google-sub` | agy | `agy` / `gemini` | the minimum of `gemini_5h` and `gemini_weekly` |
| `anthropic-sub` | claude_code | none available | not observed |
| none | agy | `agy` / `claude_gpt` | Antigravity's own Claude and GPT allowance. Despite the name it is **not** `anthropic-sub` or `openai-sub`: it is a different subscription, drawn down by AGY, and must never be read into either Claude Code's or Codex's pool. |

Two consequences for adoption. A pool's declared `window` cannot be assumed
to match the window an observation reports, so the observation must carry
its own window identity and be compared on its own terms. And the mapping
from provider and scope to pool has to be explicit configuration, not
inferred from names, because the one pair of names that looks like a match
(`claude_gpt` and `anthropic-sub`) is the one that is wrong.

## Integration shape, if adopted

Nothing below is built. It is what adoption would look like against the
mechanisms that already exist, and where those mechanisms do not fit.

- **Where.** In the `crucible` service only. The service holds the
  dedicated credential directories; workers never do (12), and a worker has
  no reason to know a pool's headroom. **Except that AGY's reading requires
  the `agy` CLI inside that service container** (it shells out to it, and
  degrades to `stale` with no rows without it). That puts a second,
  separately versioned copy of a harness CLI in the process that holds every
  credential, outside the per-image pinning ADR 0011 establishes. That is a
  real architectural cost and may be reason enough to observe Codex only.
- **How often.** On the reconcile tick, rate limited, never in the launch
  path. The measured cost is 0.5 s to 5 s per harness, AGY's path launches a
  CLI, and Codex and Claude each spend a provider request. firstmate's
  mid-task watcher polls at 60 s; a tick-rate observation is the same order
  and needs no daemon.
- **How it is stored.** As an observation row, never as authority: harness,
  pool, provider, scope, `effectivePercentRemaining`, window identity,
  runway status, `usableRunwaySeconds`, `projectedExhaustedAt`, `resetsAt`,
  confidence, `spendPriority`, the tool's `generatedAt`, the local
  observation timestamp, and a source string carrying the tool name and
  version. `--full` is never run, because only `--full` carries the
  `account` object with `accountId` and `email`.
- **How routing uses it.** As a negative signal only, at the authoritative
  check at attempt launch, where 05b already reserves pool capacity in the
  fenced transaction that moves the attempt to `launching`. A pool whose
  most recent observation is `exhausted_now`, or zero percent remaining,
  becomes ineligible. Everything else, `unknown` and stale and absent
  included, is eligible. Missing data never blocks a launch.
- **How a deferred attempt resumes, and why it is not the existing path.**
  05b's `harness_launch_deferred` looks like the right shape, and is not:
  that deferral is checked **after** the checkout lease, so a deferred
  attempt already holds the checkout, and it clears when a running attempt
  finishes. A quota deferral clears when a provider window refills, which on
  Codex's weekly bound could be two days out, and holding a checkout lease
  for two days is exactly the waste this observation exists to remove. A
  quota deferral therefore needs its own reason and must release the
  checkout before waiting, which is a change to 10 and 05b, not a reuse.
- **What it is not.** It is not the `quota_exhausted` exit class. That class
  means a harness ran and reported a limit, it is terminal for the attempt,
  and it wakes Foundry (16, 17). A pre-launch deferral on an observation is
  a different event with a different outcome, and conflating them would
  silently turn a wake into a wait. `quota_exhausted` keeps its meaning
  unchanged.
- **What Foundry and the admin status see.** `GET /routing/usage` (04, 05b)
  already reports per-pool usage and is where an observed figure belongs,
  beside the counted one, labelled as observed and carrying its own age.
  The `harnesses[]` part of `GET /v1/admin/status` (25) is where an
  observation age and last-reading outcome fit, so the operator can see when
  Crucible is routing blind. Whether the new deferral itself wakes Foundry
  is an open question for 17, not something this spike settles.

Spec changes adoption would need, listed rather than made:

1. **05b**, `RoutingPolicyV1` pools: an explicit provider-and-scope to pool
   mapping, the observation source, a staleness bound, and the rule that an
   observation can only make a pool ineligible, never eligible.
2. **05b** validation: the new fields, and the rule that an absent or stale
   observation is not a policy error.
3. **05b** and **10**: the quota deferral as its own reason, evaluated
   before the checkout lease is taken, or releasing it before waiting.
4. **17**: whether a quota deferral wakes Foundry, and with what reason.
   16's failure table is unchanged.
5. **25**: the observation fields on `harnesses[]`, and the statement that
   the reader runs in the service and never in a worker.
6. **13**: the pinning rule for a non-harness npm dependency in the
   credential path, which today's text covers only for images and harnesses;
   and, if AGY is observed, how a harness CLI inside the service container
   is pinned.
7. **12**: an explicit entry for a third-party reader that opens the
   dedicated auth files, with `--profile-only` and the scoped environment
   written down as requirements rather than as this spike's method.

## Risks

| Risk | Assessment |
|---|---|
| A third-party dependency in the credential path | Real and the largest one. quota-axi opens Crucible's dedicated auth files and sends the credential to the provider's own endpoint. Its documented posture is strong (never prints, logs, or caches a credential value; never mints, rotates, or exchanges one) and no auth file changed on any run here. Crucible cannot verify that posture continuously. The mitigations are the `--profile-only` narrowing now demonstrated by the decoy runs, one harness per call, the scoped environment, and 12's existing read-only mount of the credential directory into the `crucible` container, which would also stop any write the tool attempted. |
| AGY needs a harness CLI in the service container | Real and possibly decisive. See the integration shape above. No other provider needs this. |
| An output contract we do not own | Real but evidenced. firstmate pinned a 0.1.29 floor and a jq validator asserting `schemaVersion: 5`; at 0.1.46, seventeen releases later, the schema version and the TOON headers are unchanged. That is a track record, not a guarantee. Crucible should validate the same way: version floor, `schemaVersion`, full parse, and discard a reading that does not validate rather than act on part of one. |
| Version drift | `axi-sdk-js` is a caret range (`^0.1.10`) and resolved to 0.1.12 today, so the exact code in the credential path can change without the quota-axi version changing. A version pin alone is insufficient: the resolved tree must be pinned too, through a committed lockfile installed with `npm ci`, or by vendoring the resolved tree into the image. |
| Supply chain and pinning under 13 and ADR 0011 | 13 requires declared pins, never "the newest", reproducible builds, and recorded digests; ADR 0011 requires the updater disabled and promotion explicit. quota-axi fits that shape: pin `quota-axi@<version>` with its integrity hash recorded beside the image's other pinned inputs, install at image build from a lockfile, never at runtime, never call `update`, and let Renovate propose a bump as it does a harness bump, with a re-run of this spike's decoy and watch evidence as the promotion check. The evaluated 0.1.46 was published about thirty minutes before this spike ran, which is itself the argument for a floor plus a deliberate pin rather than tracking `latest`. |
| The tool is absent or incompatible | Must degrade to today's behaviour: no reading means every pool stays eligible, routing proceeds as it does now, and an exhausted window is discovered the way it is today, by the harness reporting it and the adapter classifying `quota_exhausted` (16). This is the condition that makes the dependency removable, and it should be an integration test rather than a comment. |
| Codex's `cli-rpc` fallback | Outside `--profile-only`, the tool may fall back to launching the Codex CLI's read-only app-server probe, which also rewrites `auth.json`. `--profile-only` disables it, and 12's read-only mount would refuse the write. A second reason the mode is not optional for Codex. |
| AGY's loopback fallback | When the `agy` CLI is unavailable, the tool discovers *already-running* Antigravity or `agy` processes and reads their loopback endpoints. On a workstation the operator's own session is such a process, so that fallback could report the operator's account rather than Crucible's. It did not fire here, and in the deployed shape the service has its own process space, but Crucible must treat an AGY reading whose source is `loopback` rather than the CLI as untrusted and discard it. |
| Claude Code has no reading | Not a risk of adopting, but a limit on the value: two of three pools observed, one not. It is why "never block on a missing reading" has to be load-bearing rather than polite. |
| The one new code path is the one never seen fire | `exhausted_now` was never observed in this spike, and it is the only reading that changes any behaviour. The first real one is a checkpoint, not a formality. |

## What was not done

- No task was run and no model called, so no reading was validated against
  an actual exhausted launch, and `exhausted_now` was never observed. The
  Codex weekly window sat at 2 percent with a projected exhaustion of 12:54
  CDT today, so the observation is available on a later date without forcing
  anything.
- No container run, and no run against a **read-only** credential mount,
  which is how 12 says the directory reaches the `crucible` container.
  Whether `--profile-only` works unchanged against a read-only directory is
  therefore not established. Everything here ran on the host as the
  operator's uid.
- No run with the operator's real `HOME` and `--profile-only`, deliberately;
  the decoy runs answer the same question without risking a read of the
  operator's credential.
- Whether a `.credentials.json`-shaped Claude session is readable was not
  tested, because the only one on this host is the operator's.
- Behaviour under the egress proxy (S6) was not tested. The tool honours
  `HTTPS_PROXY` and `NO_PROXY` and its endpoints are the providers' own, but
  the allowlist entries the service would need are not established here.
- No syscall trace: `strace` is absent and unprivileged user namespaces are
  denied on this host, so neither `bwrap` nor `unshare -r` could give a
  mount-namespace proof.
- Nothing was installed globally on the host; the evaluation install is a
  pinned scratch prefix outside the repository and is not committed.

## Recommendation

**Proceed with conditions**, as a proposed ADR (0014) for the operator's
decision, not an accepted one.

Building a per-harness reader instead would mean owning three vendor usage
endpoints, three credential-store shapes, three window taxonomies, and the
projection maths, for a signal that is advisory by construction and that
Crucible must be able to run entirely without. quota-axi already does that
work, its `--profile-only` mode is built for exactly Crucible's isolation
constraint and is now demonstrated to hold on its own, its behaviour under
missing data is to say "unknown" rather than to guess, and firstmate has run
it against the same three provider families since at least late July by its
own recorded verification dates.

The conditions are:

1. Pin by version **and** by resolved dependency tree (lockfile plus
   recorded integrity hash), installed at image build, never at runtime,
   with `update` never invoked.
2. Validate every reading: version floor, `schemaVersion`, and full parse.
   A reading that does not validate is discarded whole, not used in part.
3. `--profile-only` for Claude and Codex, one harness per call, a sanitized
   environment with a scratch `HOME` and scratch XDG roots always, `--full`
   never, and an AGY reading sourced from `loopback` discarded.
4. Observation only. A reading may make a pool ineligible; it may never make
   one eligible, and its absence or staleness never blocks a launch.
5. The quota deferral is its own reason, releases the checkout before
   waiting, and is not the `quota_exhausted` exit class.
6. An integration test that removes the binary and asserts that routing and
   launch behave exactly as they do today.
7. The first real `exhausted_now` observation is a recorded checkpoint
   before the signal is allowed to refuse a launch, and this spike's decoy
   and watch evidence is re-run on every version bump as the promotion
   check.

Whether AGY is observed at all is a separate call for the operator, because
it is the one harness whose reading puts a harness CLI inside the service
container. Codex alone would carry most of the value at none of that cost.
