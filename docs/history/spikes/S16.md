# S16: Which harness should front the DGX Spark?

Run 2026-09-20, 14:33 to 15:25 CDT, on the reference workstation and its
operator Docker daemon. The endpoint and model came only from the ignored,
untracked `.env.s16`. Its source was the lab-admin handoff at
`~/claude/lab-admin/docs/handoffs/2026-09-20-spark-local-model-server-handoff.md`.
The resident model was checked before the trials and was `gpt-oss:120b`; no
other model was requested.

Decision: **adjust design, then use the existing Claude Code adapter with a
local endpoint override, initially disabled.** Claude Code was the only
shipped, pinned worker image to pass all three specified mechanical checks.
It did not fully satisfy T3's stronger wording, as detailed below, so this is
an integration-fit decision rather than a claim that Claude Code won task
quality. It already emits the stream-json shape the adapter parses, reports
usage and terminal state, accepts the endpoint and dummy authentication by
environment, and needs no new image or harness adapter. Hermes also passed
all three container checks and was fastest on two, but it has no repository
image or adapter, its current release has no stream-json mode, and one host
run exited 0 while its usage record said the run had failed. Codex passed two
container checks, timed out on the third, and produced repeated malformed
tool calls.

This closes S13's Spark leg. The RTX 9060 leg remains open.

## Method

One fixture script, one prompt per fixture, and one mechanical checker under
the external scratch root were reused for every harness. Each attempt got a
fresh git repository. The checker used `python3 -m pytest -q` with bytecode
and pytest cache writing disabled, then checked the task-specific result and
scope. Runs had a 300 second ceiling. Pass or fail below is the checker's
result, not the harness's own claim.

The endpoint file contained only four non-secret settings: the OpenAI base
URL, Anthropic base URL, Ollama base URL, and model id. Before any commit,
`git check-ignore -v .env.s16` reported `.gitignore:14:.env.*`; `git status`
never listed it.

The host commands had these shapes, with all homes and outputs under the
scratch root:

```sh
# Codex, with the provider base_url read from .env.s16.
CODEX_HOME=<scratch>/codex-home OPENAI_API_KEY=local-no-auth \
  codex exec --skip-git-repo-check --dangerously-bypass-approvals-and-sandbox \
  --disable plugins -c check_for_update_on_startup=false \
  --model gpt-oss:120b --json -o <last-message> - < PROMPT.txt

# Claude Code, with ANTHROPIC_BASE_URL and ANTHROPIC_MODEL read from .env.s16.
CLAUDE_CONFIG_DIR=<scratch>/claude-home ANTHROPIC_AUTH_TOKEN=local-no-auth \
  CLAUDE_CODE_MAX_OUTPUT_TOKENS=8192 \
  claude -p --output-format stream-json --verbose --model gpt-oss:120b \
  --effort medium --dangerously-skip-permissions --permission-prompts none \
  --no-session-persistence "$(cat PROMPT.txt)"

# Hermes 0.19.0 in a scratch venv, with OPENAI_BASE_URL read from .env.s16.
HERMES_HOME=<scratch>/hermes-home OPENAI_API_KEY=local-no-auth \
  hermes --ignore-user-config --ignore-rules --yolo \
  --provider openai-api --model gpt-oss:120b --toolsets terminal,file \
  --usage-file <usage.json> -z "$(cat PROMPT.txt)"
```

All three host candidates passed at least two tasks, so all advanced to
Phase B. The repository's worker images were built without changing their
inputs by `images/build.sh` because their tags were absent from the operator
daemon. Their generated OCI manifest digests matched the build manifest.
Hermes has no repository image, so its Phase B image was a scratch-only build
from `python:3.12-slim` at
`sha256:2f17fc044b579bab302c2e8054d3a686e2cb9a83de48e70534b94cd8ebbe06a9`,
with Hermes 0.19.0 and git installed.

Every container ran as uid 1000 with a read-only root, all capabilities
dropped, `no-new-privileges`, per-attempt writable home and config mounts,
and tmpfs at `/tmp` and `/home/worker`. The fresh repository was the only
workspace bind. A throwaway user-defined network gave direct access to the
Spark. No proxy, credential, Compose service, Crucible service-user daemon,
or `var/egress` path was used or changed.

The pinned Codex and Claude Code images do not contain Python or pytest.
Those agents could inspect and edit but could not execute the fixture tests
inside the worker. The same external checker ran on the host after each
container exited. That is the shipped image environment being tested, not a
modified substitute.

## Egress finding

The Spark route needs destination `172.16.6.50`, TCP port `11434`, as plain
HTTP. It is not a CONNECT tunnel. The current `make proxy-config` generation
accepts hostname strings but emits only `Safe_ports 443`, `SSL_ports 443`,
and `http_access allow workers CONNECT allowed`. Therefore adding the host
to `EGRESS_ALLOWLIST` alone would still deny every Spark request.

The generation path is policy plus adapter endpoints, documented in spec 13,
into `make proxy-config`, then `make proxies`. The implementation needs a
typed endpoint destination and port derived from each enabled local
`endpoint_url`. Port 11434 must join `Safe_ports`, then the destination and
port allowance must follow the broad unsafe-port deny and precede the final
deny. In Squid terms, the relevant ordered rules need the equivalent of:

```text
acl spark dst 172.16.6.50/32
acl spark_port port 11434
acl Safe_ports port 443
acl Safe_ports port 11434
acl SSL_ports port 443
http_access deny !Safe_ports
http_access deny CONNECT !SSL_ports
http_access allow workers spark spark_port
http_access allow workers CONNECT allowed
http_access deny all
```

Adding 11434 to `Safe_ports` does not authorize it by itself, because only the
exact Spark destination-and-port rule can pass before the final deny. Port
11434 must not be added to `SSL_ports`, because that would authorize CONNECT
and widen the route beyond what this endpoint needs. This spike did not
generate or install that configuration.

## Recommended adapter shape

No new harness adapter is needed. Extend both `LaunchContext` and
`LaunchSpec` with these exact fields:

```python
endpoint: Literal["subscription", "local"] = "subscription"
endpoint_url: str | None = None
```

Validate that `local` requires `endpoint_url`, that `subscription` forbids
it, and pass the resolved routing entry through the supervisor, provider, and
provider reconstruction paths. A `LaunchContext` change alone is
insufficient: today Docker chooses credential handling from the adapter's
static `credential_spec()` and refuses Claude Code when no source exists.
The provider must branch on `LaunchSpec.endpoint`. For a local Claude Code
attempt it skips the credential copy and mount, sets
`credential_mounted=False`, and gives the adapter a fresh writable
`CLAUDE_CONFIG_DIR` containing the attribution settings above. The adapter
sets these per-attempt values:

```text
ANTHROPIC_BASE_URL=<endpoint_url with one trailing /v1 removed>
ANTHROPIC_AUTH_TOKEN=local-no-auth
ANTHROPIC_MODEL=gpt-oss:120b
CLAUDE_CONFIG_DIR=/home/worker/.claude
CLAUDE_CODE_MAX_OUTPUT_TOKENS=8192
```

The routing policy should store the OpenAI-compatible base ending in `/v1`,
as spec 05b anticipates. Claude Code's Anthropic transport appends
`/v1/messages`, so its adapter removes exactly one terminal `/v1` and does
not otherwise rewrite the configured URL. The literal dummy token is not a
credential and must never come from a secret store. Continue the existing
Claude launch, adding `--effort medium`, `--no-session-persistence`, and
`--permission-prompts none` to the current print, stream-json, verbose,
model, identity, and bypass-permissions arguments.

Exit classification stays unchanged in the existing Claude adapter.
Crucible first honors its own termination facts as `timeout`, `killed`, or
`lost`. Otherwise exit 0 is `completed` only when `report.yaml` is present,
and is `completed_without_report` only when that file is absent. Nonzero
exits continue through the existing provider-error and crash rules. The
final stream event with `type: result`, `subtype: success`, and
`is_error: false` supplies metrics and transcript-integrity evidence, not an
exit class. A missing or invalid terminal stream event needs its own recorded
parse anomaly and must fail `run_evidence_present`; it must not redefine
`completed_without_report`. A model claim or a successful stream result
never substitutes for the task report.

## Proposed routing policy

The next immutable routing version should materialize the endpoint URL from
deployment configuration when the policy is created or uploaded. The URL
must not be a repository constant. The proposed entry is:

```yaml
models:
  - id: "gpt-oss:120b"
    harness: claude_code
    endpoint: local
    endpoint_url: <configured Spark OpenAI base URL>
    capability: mid
    cost: none
    speed: medium
    pool: spark-local
    weight: 1
    enabled: false  # enable only after the proxy, project-image, and four-slot gates below
pools:
  spark-local:
    window: "1h"
    budget_units: attempts
    soft_limit: 0
    default_cooldown_seconds: 60
    max_concurrency: 4
```

`max_concurrency` is a proposed `RoutingPool` field. The existing global
per-provider and per-harness caps cannot express this safely: Claude
subscription attempts mount a writable credential and must remain at one,
while local attempts mount no credential and the Spark supports four slots.
The supervisor should enforce four on `spark-local` independently and keep
the existing credential-derived cap on subscription launches. The server
handoff reports four slots, but this spike ran attempts sequentially and did
not verify concurrent isolation or throughput. Keep the entry disabled until
a four-way load test succeeds. If that test fails, use its measured safe cap
in a later immutable policy version rather than enabling four by assumption.

No Qwen entry belongs in this version. Qwen was deliberately not evaluated,
and selecting it would change the Spark's one-resident-model box mode, evict
`gpt-oss:120b`, and reduce the documented concurrency from four to one. It
needs its own operator-approved quality and harness run before it can enter
the roster.

## Proposed implementation task

Add the two endpoint fields to `LaunchContext` and `LaunchSpec`, preserve them
through launch reconstruction, add the Claude local branch, skip all
credential handling for local attempts, create the per-attempt settings file,
resolve the Spark URL from deployment configuration into a new immutable but
disabled routing version, add pool-scoped local concurrency, and extend proxy
generation for the ordered exact plain-HTTP destination and port rules.
Unit-test URL validation and `/v1` normalization, environment and argv
construction, credential absence, attribution settings, exit classification,
transcript-integrity evidence, concurrency separation, and proxy output.
Then run a full Crucible-shaped task through the actual proxy with a
runtime-capable project image, identity and report mounts, and prove the
report, scope, and verification gates. Run four attempts concurrently and
enable the model only in the next immutable policy version if both the gate
run and the four-slot test pass.

## Limitations and open questions

- The contract named `docs/spec/13-execution-environment.md`, but that path
  does not exist at this revision. The unambiguous current document is
  `docs/spec/13-local-operation.md`, which was used and is the source cited
  above.
- The suite is three small Python and documentation tasks, one attempt each.
  It establishes harness fit, not broad model quality or stable latency.
- A direct worker network was required by the spike. The current generated
  proxy cannot carry the endpoint, so the recommended path has not completed
  an end-to-end Crucible launch.
- The pinned Codex and Claude images lack the fixture runtime. Their edits
  were checked after exit on the host. A project image that includes its test
  runtime is still needed for the normal verification contract.
- Tool counts are derived from each harness's different event surface and
  are useful within a harness, not as perfectly normalized cross-harness
  workload measures.
- The exact container runner scripts remain under the scratch root, but no
  Docker inspect or create-request capture was preserved beside each
  transcript. The uid, mount, capability, network, and digest claims were
  observed from those commands rather than independently reconstructed from
  each transcript.
- Claude's intermittent attribution trailer must be disabled by the
  per-attempt settings file and covered by a regression test before enabling
  the route.
- Hermes remains a credible later option if it gains a pinned repository
  image and a stable structured event stream. Its exit-0/failed-usage case
  must be classified from content before any adapter could safely use it.

## Adversarial review disposition

The one required non-author review blocked the first draft on four points.
All four are addressed here: Claude T3 is now recorded as a semantic failure
despite its mechanical pass; the Squid rule includes 11434 in `Safe_ports`
with the narrow destination rule in effective order; exit classification no
longer overloads `completed_without_report`; and endpoint plus credential
mode now crosses `LaunchSpec` and reconstruction rather than stopping at
`LaunchContext`.

The reviewer also raised four non-blockers. The recommendation is now
explicitly integration-first, runtime-capable validation and a four-way load
test gate enablement, token counts are declared non-comparable, and the
missing per-run Docker inspect capture is recorded above. The intermittent
Claude attribution trailer remains a known implementation gate with the
exact current setting specified.
