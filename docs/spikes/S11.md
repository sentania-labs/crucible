# S11: Can each harness be prevented from self-updating inside the container, and does it report its version reliably?

Run 2026-09-16, 14:02 to 14:20 CDT, rootful Docker 28.3.1, the three base
images in the spec 08 worker shape, network through the S6 logging proxy so
any update endpoint would show in the proxy log. S7 established the opt-outs
with `--network none`; this spike repeats with a network attached and, for
Claude Code, during a real authenticated run.

Decision: **proceed for Claude Code; partial for Codex and AGY.** No CLI
contacted an update endpoint or changed on disk; every `--version` matches
the image label; every explicit update attempt fails. Codex and AGY were
observed in unauthenticated runs only (S1 stop), so their "during a real
authenticated run" half is a C3 re-run.

## Update behaviour with a network attached

| Harness | Opt-out in effect | Run observed | Update endpoint contacted | Explicit `update` |
|---|---|---|---|---|
| Claude Code | `DISABLE_AUTOUPDATER=1`, `DISABLE_UPDATES=1` (image env) | authenticated `claude -p` through the proxy, exit 0 | none: only `api.anthropic.com`, `mcp-proxy.anthropic.com`, the Datadog intake (S6); `downloads.claude.ai` never appears | `claude update`: `Updates are disabled by your administrator. Contact your IT team to get the latest version.`, no request |
| Codex | `-c check_for_update_on_startup=false` at launch | unauthenticated `codex exec` through the proxy, with and without the flag | none either way (`github.com` appears in both, and disappears with `--disable plugins`; it is the plugin marketplace, S6) | `codex update`: `Error: Could not detect the Codex installation method.`, no request |
| AGY | `AGY_CLI_DISABLE_AUTO_UPDATE=1` (image env) | unauthenticated `agy -p` through the proxy | none (`antigravity-unleash.goog`, `play.googleapis.com`, Playwright CDN are not the updater; neither `storage.googleapis.com`, where S7 found the release tarballs, nor `antigravity.google`, where the installer lives, appears) | `agy update`: `Checking for updates... (current version 1.2.4)` then `Error: directory /usr/local/bin is not fully accessible (readable: true, writable: false)`, and no request reached the proxy before it failed |

Filesystem after each run: the root is read-only, so an update could not
land in any case; `/usr/local/bin/<cli>` is unchanged by construction.

## Notes

- The Codex opt-out is a launch flag, not image state (S7); the adapter
  must keep passing it, and this spike could not distinguish its effect
  because the CLI made no update request either way. The github.com
  contacts that looked like an update check are plugin sync.
- AGY's explicit `update` still prints "Checking for updates" with the
  variable set (as in S7) but did not reach the network before failing on
  the read-only directory; whether it would have is unknowable from this
  run and moot under the read-only root.
- Repeat per promotion (ADR 0011): the two tables above are the check.
