# S3: Does AGY operate headless with `--add-dir` and a pointer prompt, and what is its real argv ceiling?

Run 2026-09-16, 13:59 CDT (authenticated run) and 14:05 CDT (argv
measurements), image `crucible-worker:agy-1.2.4-a0f410dd9e78`, spec 08
worker shape, rootful daemon.

Decision: **proceed, partial.** Headless mode with the spec 07 flags works
and the ceiling is measured; the 100 KB identity bundle with `--add-dir`
and the `AGENTS.md` check are not done, because the one authenticated run
(S1) refreshed the OAuth token on its own and the task contract stops
AGY's authenticated runs at that point.

## Headless run (from S1, authenticated, `ro` mount)

```
agy -p "Reply with exactly the word PONG and nothing else." \
    --dangerously-skip-permissions --add-dir /crucible/identity --output-format stream-json
```

Exit 0 in 22 s. stdout is one JSON object per line: `init` (cwd, tool list),
`step_update` (user_input, then agent_response with `text_delta` and usage),
and a final `result` with `status`, `response`, `duration_seconds`,
`num_turns` and token usage. stderr is the CLI's glog stream (hundreds of
lines, including the language-server startup and the auth log). Every flag
in spec 07's launch line is accepted by 1.2.4; `--model` and `--effort`
are listed in `agy --help` (`--model  Model for the current CLI session`,
`--effort  Reasoning effort for the current CLI session (low|medium|high)`)
but were not passed, so those two flags are listed, not confirmed, and
the default model answered. The other four flags in spec 07's line are
confirmed by the run.

Unauthenticated, the same command exits 1 with the same shape:
`{"conversation_id":"","status":"ERROR","response":"","error":"authentication failed or timed out",...}`
and `Error: authentication required. Run 'agy' to log in, then retry.` on
stderr. `status` in the `result` line is the field to parse.

## The argv ceiling

Measured inside the container with `--network none` and no credential:
the CLI is exec'd with one argument of N x 1024 bytes of `a` (KiB
throughout); a run that starts prints the OAuth login URL and exits 1, a
run that does not start fails in `execve` (bash reports exit 126, `E2BIG`).

```
$ getconf ARG_MAX        2097152      (2 MiB total for argv plus environment)
$ ulimit -s              8192         (ARG_MAX is stack/4)
MAX_ARG_STRLEN = 32 * PAGE_SIZE = 131072   (kernel constant, computed from getconf PAGESIZE)

single arg   64 KiB: started, reached auth
single arg  100 KiB: started, reached auth
single arg  127 KiB: started, reached auth
single arg  128 KiB: execve failed (E2BIG)
single arg  129 KiB .. 2000 KiB: execve failed
two args of 100 KiB each (200 KiB total): started, reached auth
```

So the "128 KB argv ceiling" in spec 07 is the Linux per-argument limit
(`MAX_ARG_STRLEN`, 128 KiB minus the terminator), not anything in AGY. The
total budget is 2 MiB shared with the environment. AGY imposes no smaller
limit of its own below that, at least up to the point where the prompt is
parsed. The design rule stands regardless: identity and contract are files,
argv carries a pointer under 1 KB.
