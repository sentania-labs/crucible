# C10: authenticated lab-local gateway

## Delivered behavior

- The lab CA is committed at `images/ca/sentania-lab-root.crt`, pinned by raw-file
  SHA-256 `567f110bb80bb2179b44995c78c7a49a4149085a59f6acb73cf37c6503a0481a`, and
  installed in every worker image. The three standard certificate-bundle variables
  point at the merged system bundle.
- Hermes declares optional read-only credential file `api-key`. A configured key is
  mapped to `OPENAI_API_KEY` from the mounted file and is never synced back. Without the
  `api-key` file, whether no source is configured or the source is the empty directory
  Compose's `credential-init` creates, nothing is mounted and the explicit
  `local-no-auth` placeholder preserves compatibility with unauthenticated
  OpenAI-compatible endpoints.
- The migration clones the routing policy that the latest non-retired
  `default-software` policy names (the same definition of "in force" the admin routing
  code uses), under that routing policy's own name. It never clones a higher-numbered
  draft nothing references. The highest stored versions only number the new rows,
  version 6 on an unmodified database. The clone removes the `gpt-oss:120b` pin and
  creates disabled model `coder` in pool `lab-local`. The operator can edit the endpoint
  URL, model enablement, thinking preference, and pool concurrency in the UI, API, or
  CLI. The API takes `enabled` and `enable_thinking` as JSON booleans only and answers
  anything else with a 422, so the string `"false"` cannot enable a model. Each save creates
  new immutable routing and delivery policy versions and regenerates the Docker proxy
  configuration. The active proxy file lives in a named volume writable by the app;
  atomic replacement signals the running Squid process to validate and reload it.
- The Hermes key paste writes one mode-0600 file atomically. It returns no key, logs no
  key, and emits only the `credential_set` audit event. Validation checks readiness
  without authentication before checking `/v1/models` with the bearer.
- Docker and Kubernetes resolve the configured gateway hostname to exact destination
  addresses and keep the configured port exact. Kubernetes refuses a local endpoint
  URL that directly names an API, namespace, node, link-local, or other denied address.

## Environment and recovery

`CRUCIBLE_LOCAL_ENDPOINT_URL` is only a first-migration seed. The old
`CRUCIBLE_SPARK_ENDPOINT_URL` name remains a compatibility seed. Once routing version 6
exists, the active database policy is authoritative and a restart cannot overwrite it
from either environment value.

Recovery is bounded and reversible: disable `coder` or select the preceding immutable
policy version. The save regenerates and reloads the proxy configuration. Key
replacement uses the same paste operation. The previous policy documents remain in the
database, and no public DNS operation is part of this path.

## Hermes thinking limitation

Hermes 0.19.0 does not expose a safe non-interactive CLI option for passing
`chat_template_kwargs.enable_thinking` on each run. C10 stores the operator's choice in
the routing entry so it survives policy versioning, but does not claim that the current
Hermes transport sent it to the gateway. This is a retained intent field until the
adapter gains a supported transport.

## Issue 57

The Kubernetes local-endpoint exception now uses only the configured, resolved gateway
hostname and port. A private result must also fit the operator-declared
`local_endpoint_cidrs`; the base carries an empty list and the lab overlay's
`REPLACE_ME_LOCAL_ENDPOINT_CIDRS` placeholder sets the one address lab-admin allows. A
direct denied IP, the API Service address, or another namespace address is refused
before a NetworkPolicy is created. This closes the bypass described by issue 57 without
broadening the general hostname allowlist.

## PR 82 review corrections

- Migration seed source: 0017 read the highest routing version, so an unreferenced
  draft would have become the new default. It now follows the in-force policy's
  reference, including a routing policy uploaded under a name other than
  `default-routing`.
- Empty credential directory: the supervisor and the Docker provider counted the Hermes
  directory as mounted before `api-key` existed, so the launch named a key file that was
  not there. `CredentialSpec.held_by` now requires an optional credential's required
  auth files.
- Non-boolean flags: `bool("false")` enabled a model and its proxy destination. The API
  rejects non-booleans with a 422 and the service only turns a flag on for a real `true`.

## Kind tier flake candidate

CI run 35789531232, attempt 1 (job `e2e-kind`, 2026-09-22 4:56 PM to 5:05 PM Central):
`test_row_5_7_11_full_lifecycle_on_a_real_pod_and_pvc` observed `lost` with detail
`the Job has no Pod`; 9 of 10 passed. The re-run (attempt 2, 5:05 PM to 5:14 PM) passed
all ten, and the tier passed on the workstation. The fresh runner's cluster was slow to
settle: calico-node reported `BIRD is not ready`, calico-kube-controllers and coredns
failed readiness and sandbox creation before the CNI was up, and coredns rolled a second
replica set. The worker Job itself completed normally (`Job completed` about four
seconds after its Pod was created).

The detail points at the provider's observe path rather than at this branch:
`KubernetesProvider._observation_without_pod` answers `lost` for a Job with no Pod and
no terminal condition unless the attempt has been pending too long. A first observe
that reads the Job before the Job controller has created the Pod, on a loaded
controller, would take that branch. That code is unchanged by C10. The branch's
Kubernetes changes (local endpoint resolution and containment, local endpoint CIDRs,
the optional credential copy) apply only to a local endpoint or a declared credential,
and the lifecycle case runs the script harness on a subscription route with neither.
Recorded as a flake candidate, not fixed here.
