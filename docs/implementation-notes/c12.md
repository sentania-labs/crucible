# C12: one `crucible` command with an envelope an agent can act on

## Result

`crucible` is the one client. `crucible serve` is unchanged; `crucible admin` is
everything `crucible-admin` did, with the same arguments; the orchestrator verbs are
everything Foundry's `foundry-crucible` did, verb for verb, at the top level. Every
command but `serve` prints one JSON envelope (docs/client.md). The shared library is
`crucible/client/`; an import-linter contract keeps it free of the server's
application, adapters, and frameworks, so a later MCP server can sit on it alone.

`crucible-admin` is a shim that prints one deprecation line on stderr. Foundry's
replacement shim is `docs/integration/foundry-crucible-shim/`; Crucible does not
install it.

## Decisions where the contract was open

- **The orchestrator verbs are top-level, not under a `tasks` group.** Foundry's own
  verbs are `tasks`, `task`, `wakes`, `submit`, and so on; carrying them unchanged at
  the top level makes `foundry-crucible ARGS` exactly `crucible ARGS`, so the shim
  execs `crucible` with the same arguments and nothing is renamed.
- **The role comes from the API.** There is no endpoint that names the caller, and the
  contract rules out new endpoints. A verb whose route admits one role class proves the
  role by succeeding; otherwise two read-only probes ask the guards themselves
  (`GET /v1/admin/audit?limit=1`, `GET /v1/capabilities`). An unknown role offers
  nothing. An operator and an orchestrator pass the same guards, so both show as
  `orchestrator` and are offered what both may do.
- **Ownership is named, not guessed.** The client cannot learn its own principal's name,
  so an action on a task carries `requires.owner` (the task's principal) wherever the
  service checks ownership.
- **`next` mirrors the server's guards and is tested against them.** The state sets are
  asserted equal to the domain's and the services' own (`_CANCELLABLE_AT_ONCE`,
  `CORRECTABLE_STATES`, the transitions into `closed`); every offered argv parses; and
  the live integration test runs an offered `start` exactly as offered.
- **Exit codes follow the contract.** A refusal exits 1 (the admin client used 2) and an
  unreachable server exits 1 (Foundry's client used 3). Usage and configuration exit 2.
- **The first-run administrator token moved to stderr.** stdout carries the envelope
  alone; `docker compose logs migrate` and the Kubernetes Job's log still show the banner.
- **The envelope has two fields beyond the contract's list:** `envelope` (its version)
  and `principal_role`.

## Parity, proven

`tests/fixtures_data/legacy_cli/trees.json` holds both old command trees, captured by
`capture.py` beside it from `crucible-admin` at c7cd915 and `foundry-crucible` at
Foundry 0cb2401. `tests/unit/test_cli_parity.py` asserts every old path maps to a new
one with the same positionals and option shapes (name, dest, required, choices, type,
default), and that every admin verb makes the same remote call. The orchestrator verbs'
request shapes are Foundry's own tests, ported to read the envelope
(`test_cli_orchestrator.py`). `tests/integration/test_admin.py`,
`test_bootstrap_import.py`, and `tests/e2e/test_admin_live.py` now drive
`crucible admin`.

## Rebased onto C10

The branch rebased onto `main` at 6198913 (C10: the lab root CA and authenticated
Hermes). C10 added three admin verbs, which now carry the same treatment as every other
admin verb:

- `crucible admin credentials set --harness hermes`: reads the LiteLLM virtual key from
  stdin or a hidden prompt (never argv), same as `_read_api_key` for every other secret
  this CLI takes. Its `next` offers it only for `hermes` and only from `absent` or
  `invalid`, since it is the API-key path rather than a login.
- `crucible admin routing local-endpoint`: a read; its `kind` is `local_endpoint`.
- `crucible admin routing set-local-endpoint --endpoint-url --model [--enable|--disable]
  [--enable-thinking] [--max-concurrency]`: the same `kind`. `next` offers
  `set-local-endpoint` from a read, since the panel always accepts an update; the
  current values are advisory context, not a default the client assumes for the caller.

The legacy tree fixture was recaptured from `crucible-admin` at 6198913 (the admin
module main carried before this branch's rewrite), which is the only side that changed;
`foundry-crucible`'s tree is untouched. `tests/unit/test_cli_parity.py` gained rows for
the three verbs, and `crucible/client/schema.py` gained the `local_endpoint` schema.

## Rebased onto C11

The branch rebased onto `main` at c7cd915 (C11: one worker image, built in CI and
published by the release). C11 did not touch `crucible/cli/admin.py`, so the command
tree itself is unchanged; the legacy fixture was recaptured anyway, from
`crucible-admin` at the new main tip, to hold the ref current
(`tests/unit/test_cli_parity.py`'s own ref assertion moved with it).

What C11 did change is the image record's shape: an `ImageView` now carries `harnesses`
(every harness the image carries, name to pinned version) instead of a single `harness`
and `harness_version`, since one worker image now carries all four. `crucible schema`
picks this up for free through `_model(ImageView)`. The one place that still read the
old singular field was `crucible.client.next.image_actions`, which gated a promote
action on `item.get("harness")`; it now gates on `item.get("harnesses")`, since an image
with no declared harness offers nothing to promote either way.

## Seen working

- `tests/integration/test_cli_live.py` runs the real API on a real port and drives
  `crucible` with an orchestrator, operator, admin, and observer token: submit, follow
  `next` to start, read, list; the API's refusals (forbidden, transition-not-allowed)
  come back whole in the envelope; `crucible admin --api-url` against the same server.
- The service image built from this branch ran `crucible admin migrate` against a
  throwaway PostgreSQL: exit 0, the envelope alone on stdout, the banner on stderr.
  `crucible-admin token create` in the same image printed the deprecation line and a
  `supervisor-not-live` envelope with exit 1, which is the guard working (no supervisor
  ran there).
- The live administration tier (`make e2e-admin`) was not run: it needs the dedicated
  credential root, which this workstation session had no access to. Its module is
  ported and skips cleanly without it.

## Open

- The orchestrator probe, `GET /v1/capabilities`, computes the full status document on
  the server, so a read with an orchestrator token costs that once per command. A
  cheaper read-only orchestrator-guarded route would remove it; that is an API change.
- `bootstrap commit` is offered on any verified import; the service refuses it when
  another import is already authoritative, which the single record cannot show.
