# C5 implementation notes: harness adapters live

Phase C5 per `docs/spec/20-implementation-phases.md`, delivered in two pull requests:
C5a (this one) is the `HarnessAdapter` port, the three real adapters and the script
harness behind it, the per-attempt credential copy of 12, report parsing and exit
classification from real runs, version pinning with refusal, `GET /harnesses` and `GET
/images`, and the `e2e-live` tier. C5b is the admin API and credential onboarding (25).
Where the specification left something open, the simplest choice consistent with it was
taken and is recorded here. Nothing here changes the specification; proposed changes are
listed at the end.

## Decisions

1. **The credential copy is a workspace directory, not a Docker volume.** 12 says "a
   per-attempt Docker volume seeded with only the named auth files". A named volume
   cannot be removed while any container references it, and the worker container has
   to outlive the run until its logs are drained (08), so a volume could not be
   "removed at once after the sync-back". The copy is the `credential` leaf of the
   attempt's workspace instead: the preparer creates it (mode 700, owned by container
   uid 1000, so on the host it belongs to a subordinate uid no other user can read, S9
   Test E), the provider seeds it through the daemon's archive endpoint into the
   created, not yet started, worker, and a cleaner container removes it inside `collect`
   right after the read-back. Same guarantees as the volume, plus immediate removal.
2. **Seeding and read-back go through `PUT` and `GET /containers/{id}/archive`.** The
   value travels in the request body and nowhere else: not `Env`, not `Cmd`, not a bind
   source, not this process's argv. The daemon extracts the tar with the ownership the
   headers carry (uid 1000, mode 600) and mounts the container's declared mounts to do
   so, which is also why the tar carries no placeholder for the read-only template file:
   a file at the template's path collided with the mount point (found live).
3. **The Claude Code token reaches the CLI through a launch wrapper inside the
   container.** 07 allows the long-lived token to be delivered through the CLI's
   documented variable "from the mounted file at container start". The create request
   carries `CRUCIBLE_ENV_FROM_FILES=CLAUDE_CODE_OAUTH_TOKEN=/home/worker/.claude/oauth-token`,
   a name and a path; a bash wrapper (`docker.py:LAUNCH_WRAPPER`) reads the file and
   exports the variable before `exec`ing the harness. The same wrapper feeds the prompt
   on stdin (IDENTITY.md first for Codex, 07) and tees the harness's stdout into
   `report/transcript.jsonl`, so the transcript becomes an artifact by the collector's
   ordinary report copy. A launch that needs none of that (the script harness) keeps a
   plain argv, which is why the C3 e2e tier is unchanged.
4. **Only files with an issued-at are ever written back.** 12 says "choosing by the
   newest issued-at timestamp inside the token, never by exit order". Codex orders by
   `last_refresh`, AGY by `token.expiry`. Claude Code's `oauth-token` is opaque and never
   refreshes (S1b), and `.claude.json` is state the CLI rewrites on every run (S1), so
   both are seeded and neither is synced back; the record says "changed; state, never
   written back". A file that is not the expected JSON shape, or not newer than the
   source as it is now, is recorded and not written. Writes are a temporary file plus
   `os.replace`, mode 600.
5. **Two enable gates, both required.** Configuration (`[harnesses.<name>]`) is the
   operator's static gate and the seeded `harnesses` row (migration 0008) is the
   administrator's runtime flag that C5b's `harnesses enable|disable` flips without
   touching configuration (25: "configuration retained"). A launch needs both; the
   reasons of both appear in `GET /harnesses`. Codex and AGY ship disabled in both, per
   the operator's rule for this phase; the live tier enables the harness under test in
   its own scratch database with a recorded test-only reason.
6. **A refusal is not retried.** An unknown or disabled harness, a version outside the
   adapter's range, or a missing credential ends the attempt as `environment` with a
   `harness_refused` event and a `harness_unavailable` wake, and the retry rule skips
   it: the same refusal would come back. Foundry has the wake.
7. **Per-harness concurrency is checked after the checkout lease, not before.** 05b's
   cap (1 whenever the credential mounts rw-narrow) held back a second attempt on the
   same branch before 10's lease could say why; the lease is the older and more
   specific rule, so it goes first and the cap applies only to a launch that could
   take the checkout.
8. **Exit classification is the adapter's, from both tails, on a non-zero exit only.**
   S5's table with the domain's deterministic code first; the auth and quota patterns
   never turn exit 0 into a failure (Claude Code's `rate_limit_event` lines appear on
   successful runs) and never reclassify a termination Crucible performed.
9. **Tokens and cost come from the transcript onto the attempt metrics.** Claude Code's
   `result` line (`usage`, `total_cost_usd`, `modelUsage`), Codex's `turn.completed`
   usage summed over turns, AGY's `result` usage. A harness that reports nothing leaves
   null and the pool counts attempts (05b, routing.py unchanged).
10. **`GET /images` reads the daemon; promotion state is a table.** Every image carrying
    the `crucible.harness` label is listed with its digest and whether the adapter's
    range supports its version; `image_promotions` records `default` and `retained` for
    C5b's promote and is `candidate` until then.
11. **The templates live inside the identity bundle.** 12 mounts the rest of the config
    directory read-only from a Crucible-owned template. The template files are written
    to `identity/harness/` before the bundle is hashed, so the bundle hash covers them,
    and each is bind-mounted read-only on top of the copy at the CLI's path (a file
    subpath of the artifact volume in normal mode; verified on the daemon).
12. **`chatgpt.com` joins the Codex endpoints.** S6 left it conditional on an
    authenticated re-run. The first live Codex run reconnected to it 105 times through
    the filtering proxy and never reached the model; with `auth_mode = chatgpt` the
    ChatGPT-plan backend is that host. `ab.chatgpt.com` stays denied.
13. **`www.googleapis.com` and `lh3.googleusercontent.com` join the AGY endpoints.**
    Before any turn the 1.2.4 CLI runs an "eligibility check": the userinfo endpoint on
    the first host, then the account's profile picture from the second, and it fails
    closed when either is refused (found live, two runs). Neither is a model endpoint;
    both are what the CLI needs. `antigravity-unleash.goog`, `play.googleapis.com` and
    the Playwright CDN stay denied and the run completes without them.
14. **AGY's minimum mount mode is `rw-narrow`.** 12 started it at `ro` pending a run
    that showed a rotated token. The first Crucible-side AGY run after the one-hour
    expiry (00:50 CDT on 2026-09-17) refreshed the token, the copy carried a newer
    `token.expiry`, and the sync-back wrote it to the dedicated directory. That is the
    Crucible-side refresh S1b step 5 waited for; step 6 (the operator's own session
    afterwards) is Foundry's check, outside this repository. `RW_NARROW_HARNESSES`
    now names all three, so the policy check holds their concurrency at 1.
15. **AGY's stream is keyed by `event`, and its effort is part of the model id.** S3
    described `type`-keyed lines; the CLI emits `{"event": "result", "result": {...}}`.
    The adapter reads both. `--effort` is refused for the Flash models ("Gemini 3.8
    Flash (Low)" is `gemini-3.8-flash-low`), so the live tier passes none for AGY.
16. **Codex with a ChatGPT-plan login accepts `gpt-5.5`.** The `-codex`-suffixed ids
    the binary carries and `gpt-5.6` are refused by the API for a ChatGPT account;
    `gpt-5.6-luna` and `gpt-5.6-terra` are accepted but the CLI then fails closed on
    the missing `codex-code-mode-host` (S1 saw the same message as non-fatal on the
    default model). `gpt-5.5` completed the task in 61 s. The image carries no
    code-mode host on purpose (13: the CLI and nothing else), so those two ids wait on
    a decision about the image.
17. **`default-routing` version 2 carries the verified ids.** Version 1's ids were
    placeholders (`gpt-5-codex-mini`, `gemini-3-pro`); a policy version references it
    and it is immutable (05b), so 0008 seeds version 2 beside it and a deployment's
    policy names version 2 to use the real names. The non-trivial-tier entries
    (`claude-sonnet-5`, `gemini-3.8-flash-high`, `gemini-3.1-pro-high`) are the CLIs'
    own listed ids and were not run in this phase.

## The correction round

Ten findings from Foundry's internal reviewer, all fixed:

18. **A credential copy is removed on every path that skips collect.** A start that
    failed after seeding, and a worker the daemon lost, left the seeded files in the
    workspace leaf, and neither path ever set `logs_drained`, so cleanup and retention
    never visited them. The provider removes the leaf itself on a failed start, exposes
    `discard(ws, spec)` for the supervisor's lost and launch-failure paths, and
    `cleanup` removes the leaf under every policy, `keep` included.
19. **The per-harness cap counts an attempt until its copy is gone.** `terminating`
    and `exited` attempts still hold their copy until collect syncs it back; a second
    seeding from the source before that is the refresh race 12 names, so both states
    count toward the cap.
20. **`make scan` knows the harness token shapes.** `.gitleaks.toml` extends the
    default rules with every pattern in `crucible/domain/secrets.py`, and a unit test
    holds the two lists equal. The Codex refresh token gained a pattern of its own:
    it is not a JWT (two short base64url segments and one long one, from a real
    `auth.json`; shape only, never a value).
21. **Worker log chunks pass through the redaction filter before storage** (12). The
    resume position keeps the raw line's hash, which is what the daemon's stream is
    compared against.
22. **The AGY quota patterns lose the bare `429`**, which matched any three digits in
    a 64 KiB tail; `Too Many Requests` carries the context.
23. **AGY ships enabled.** Decision 14 recorded the Crucible-side refresh (00:50 CDT,
    S1b step 5); Foundry then confirmed the operator's own AGY session answered and
    refreshed normally at 06:32 CDT (step 6). Both gates now say so in the example
    configuration, compose, and the seeded row; Codex keeps its accurate reason.
24. **A disabled harness is a contract problem at submit** (`execution_request.harness`),
    not a refusal a task later.
25. **Operator-facing prose carries no UTC stamp**; the structured field does.
26. **`attempt_metrics.model_reported`** records the model the transcript named beside
    the one the contract requested, and `GET /routing/history` returns both.
27. **The Codex roster is the operator's: Luna, Terra, Sol, Astra.** The ids come from
    the CLI's own listing, read from the `models_cache.json` the CLI writes beside its
    auth file at start (a probe in the hardened image with the dedicated credential and
    a deliberately invalid model id, 07:05:59 CDT, no turn run, copy removed). The
    listing carries no cost classes; those are Foundry's tiering.

    | id | display name | visibility | priority | default reasoning | tier (Foundry) |
    |---|---|---|---|---|---|
    | `gpt-6-astra` | GPT-6-Astra | list | 1 | medium | frontier |
    | `gpt-5.6-sol` | GPT-5.6-Sol | list | 4 | low | frontier |
    | `gpt-5.6-terra` | GPT-5.6-Terra | list | 7 | medium | standard (mid) |
    | `gpt-5.6-luna` | GPT-5.6-Luna | list | 8 | medium | trivial (small) |
    | `gpt-5.5` | GPT-5.5 | list | 12 | medium | not in the roster |

    Two hidden entries (`gpt-reserve`, `codex-auto-review`) are not models a worker
    names. `default-routing` version 2 seeds the four at those tiers; `gpt-5.5` is
    out of the pool.
28. **The Codex image carries `codex-code-mode-host`.** The 5.6 family failed closed
    on 2026-09-17 at 00:48 CDT because the CLI spawns a companion binary for those
    models. It is an asset of the same `rust-v0.153.4` release
    (`codex-code-mode-host-x86_64-unknown-linux-musl.tar.gz`, static musl, with its
    own `.sigstore`), so it meets the image rules (13, S11) the same way the CLI does:
    pinned by version and by the tarball's sha256, mtime set to the epoch, no network
    at run time. First built with an unmodified `images/build.sh` on the rootless daemon
    as `crucible-worker:codex-0.153.4-79543cafffd2` (OCI digest
    `sha256:9992602b27…ec863`); decision 33 then changed `build.sh`, which retags every
    image, so the current tag is the one in `images/manifest.env`
    (`codex-0.153.4-ce72fc1b2e20`, digest `sha256:173f6031db…eaf56`). The previous
    tags stay on the daemon as the rollback (13). The reproducibility check across a
    second daemon (C3 did it for the three images) was not repeated for these builds.
    Luna then ran the live task twice on the first rebuilt image:
    the first run (07:14 CDT) exited 0 without writing `report.yaml` and failed the
    report gate as designed, the second (07:17 CDT) reached `ready_for_merge` in 62 s
    with the code-mode host in use. The same non-determinism haiku showed (limitations).

## The second correction round

Four findings from the provider's review of the corrected head, all fixed:

29. **The harness label is required.** An image with no `crucible.harness` label was
    accepted on its version label alone; it is refused now, before any credential is
    seeded, and only an exact match with the requested harness launches. All four
    worker images carry the label.
30. **The credential copy is removed in a `finally` path.** A transport failure during
    the read-back (a timeout, a socket error) left the copy on disk and the attempt
    retried against it; each file's read failure is recorded and the copy goes
    regardless.
31. **The kernel's OOM kill reaches classification.** `Observation.oom_killed` is a
    flag the provider sets from `OOMKilled`; a worker killed that way at exit 137 is
    `environment` (S5), so a policy that retries environment failures does.
32. **Progress lines are events.** Each parsed `progress.jsonl` entry is a
    `worker_progress` event under the principal `worker`, `verified: false`, at most
    200 per attempt and 1000 characters per line, redacted line by line (07).

33. **The image per harness is a declared pin, never "the newest".** Foundry's own run
    of the live tier at 07:26 CDT picked the old Codex tag for Luna: every reproducible
    image carries the same `SOURCE_DATE_EPOCH` creation time, so two tags of one
    harness tie and `daemon.image_tag` chose arbitrarily. `images/build.sh` now writes
    `images/manifest.env` (tag and OCI digest per harness; not a build input, so
    recording never changes a tag), the e2e and live tiers read it, and `image_tag`
    refuses when more than one tag matches and the manifest pins none. Editing
    `build.sh` changes every image's tag (it is a hashed input), so all four were
    rebuilt on the rootless daemon and the manifest records them:

    | Harness | Tag | OCI manifest digest |

    | claude_code | `crucible-worker:claude_code-2.1.273-8b75176f203e` | `sha256:b7aa26be061de6c33be91f1d66c8033904bb7b5dbed6e8d2e4fd1998f9115d0d` |
    | codex | `crucible-worker:codex-0.153.4-ce72fc1b2e20` | `sha256:173f6031db3799331538c17eff7f04e4e802b71e6e9de0f496567feae15eaf56` |

    CI builds the script image with the same inputs and so the same tag, which is how
    its e2e job and the pin agree without a push.

## The live tier

`make e2e-live HARNESS=<name>` with the dedicated credential root and the C4 tier's
GitHub inputs. Per harness: a trivial task (append one line to `notes/c5-live.txt`,
commit with the attempt trailer, write the report) in the hardened image with the
credential seeded into a uid-1000 per-attempt copy, to a collected head, the gates, an
internal review, acceptance, publication, and `ready_for_merge` on the throwaway
repository; cleanup closes the pull request and deletes the branch. The run records the
local time, the model requested and the model the transcript named, the duration, the
exit class, the mount mode, whether each named auth file changed (by hash, in memory),
and the state reached; it asserts that none of the credential values, read into memory
once, appears in the worker's create request, the events, any text column, the log
chunks, the artifact store, or the pull request. The per-harness results are in the
phase report, not here.

## Where this differs from the specification

- **12, the copy's shape.** A workspace directory rather than a Docker volume (decision
  1). The properties 12 wants (only the named files, uid 1000, removed at once, never
  shared) all hold; the mechanism differs.
- **13, "one credential mount".** The read-only template is a second mount at a path
  inside the credential directory (decision 11). It is Crucible's own file from the
  identity bundle, not a second credential.
- **07, `classify_exit(exit, stderr_tail)`.** Takes both tails, as S5 asked.

## Proposed specification changes

1. **12.** Say "a per-attempt copy owned by the worker's uid, seeded through the
   daemon" rather than "a Docker volume", or state that immediate removal is the
   requirement and the mechanism is the provider's. Add that the copy is seeded before
   the worker starts and read back after it exits through the container's archive
   endpoint, never through a mount the Crucible process reads.
2. **07, Claude Code.** Record that the dedicated Crucible session uses the long-lived
   token (S1b) as `oauth-token` beside `.claude.json`, that neither is written back, and
   that `CLAUDE_CONFIG_DIR` points at the copy.
3. **07 and S6, endpoints.** Codex: `chatgpt.com` is required for a ChatGPT-plan login.
   AGY: `www.googleapis.com` and `lh3.googleusercontent.com` for the eligibility check.
   Promote both lists from provisional; the Claude Code list (`api.anthropic.com`
   alone) completed a task through the filter and is promoted too.
4. **07 and 12, AGY.** `credential:agy` is `rw-narrow` (decision 14); `--effort` is
   inside the model id for Flash; `--print-timeout` follows the attempt's timeout (the
   CLI's default is five minutes and would cut a longer task); the stream is keyed by
   `event`.
5. **13, "one credential mount".** Name the read-only template mount.
6. **25, enablement.** Name the two gates (configuration and the administrator's flag)
   and that a launch needs both.
7. **05b and 12, concurrency.** State the order with the checkout lease (decision 7).
8. **10.** The event kinds `harness_refused`, `harness_launch_deferred`,
   `harness_enabled`, `harness_disabled`, `credential_synced`; the wake reason
   `harness_unavailable`.
10. **12 and 08.** A credential copy is removed on every path, including a failed
    start and a lost worker, and `cleanup` removes it under `keep`; 08's "keep or
    delete the workspace per policy" should exclude the credential copy. The
    per-harness cap holds until the copy is gone, which is after `exited`.
11. **12, log redaction.** Worker log chunks are redacted before storage; the resume
    hash stays that of the raw line.
12. **03 and 14, `attempt_metrics.model_reported`.**
9. **14.** The `harnesses` and `image_promotions` tables, written by the supervisor
   (observations) and by the admin surface (flags); neither is fenced because both
   principals write them.

## Limitations

- A small model does not always follow the reporting protocol: on one Claude Code run
  out of two, `claude-haiku-4-5` made the change but wrote no `report.yaml`, and the
  run ended `completed_without_report` with `report_present` failing. The gates did
  their job; the routing question (which cheap model is reliable enough for trivial
  work) is Foundry's to answer from the recorded outcomes.
- The AGY templates are empty: its config directory carries no settings file the
  adapter needs to pin, and `config/` is not seeded. `mcp_config.json` under it is not
  mounted read-only.
- Codex's roster runs on the rebuilt image (decision 28); `gpt-5.5` is the recorded
  fallback outside the pool. Luna, like haiku, sometimes exits 0 without a report; the
  gates catch it and the outcome is recorded for routing.
- The Codex Crucible-side refresh (S1b step 5 for Codex) did not occur: `auth.json`
  was unchanged on every Codex run, its token still valid from the 17:08 CDT login.
  Codex therefore stays disabled in the shipped defaults.
- The AGY transcript carries the account's profile-picture URL from the eligibility
  check: an account identifier, not a secret. It is stored as an artifact like the rest
  of the stream; nothing of it is in a fixture.
- Quota exhaustion was not triggered live; the patterns are from the CLIs' known
  phrases and the S1 observation of `rate_limit_event`, with unit fixtures.
- `image_promotions` has no writer until C5b.
