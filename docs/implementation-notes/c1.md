# C1 implementation notes: walking skeleton

Phase C1 per `docs/spec/20-implementation-phases.md`. Where the specification
left something open, the simplest choice consistent with it was taken and is
recorded here. Nothing here changes the specification; proposed spec changes
are listed at the end.

## Layout

`crucible/domain` (pure), `contracts`, `application`, `ports`, `adapters`
(`api`, `persistence`, `execution`), `scheduler`, `cli`, plus two top-level
modules outside the layer stack: `settings.py` (Pydantic settings) and
`logs.py` (JSON logging and the id context). import-linter enforces the inward
rule and forbids frameworks in the domain, contracts, ports, and application.

## Decisions

1. **`POST /tasks/{id}/start` records the dispatch; the supervisor materializes
   it.** Execution and attempt rows are fenced to the supervisor's token (14),
   so the API cannot create them. `start` moves the task to `scheduled` and
   writes `task_scheduled` with the execution request; the next tick creates
   the execution and attempt 1. Overrides are refused in C1 (they are an
   amendment, C2); the start body must agree with the contract.
2. **The task moves `scheduled -> running` when its attempt begins
   `preparing`.** A prepare or launch failure then lands in `reported` through
   the normal path; `scheduled -> reported` is not a transition in 09.
3. **Timeout keeps the attempt in `running` while draining.** `drain_deadline`
   and `termination_reason` columns record the drain; the kill fires when the
   deadline passes; the exit is classified `timeout`. Cancellation uses
   `terminating` and classifies `killed`. Both paths are in the attempt table.
4. **A blocked task leaves its execution `active`.** The decision path that
   reschedules a blocked task is C2, so nothing closes the execution yet.
5. **Retry.** A failed attempt retries when its exit class is in the
   contract's `retry_on` (already validated as a subset of the policy's
   eligible classes) and attempts remain. The next attempt is created in the
   same transaction as the retry decision; the task returns to `scheduled`.
6. **Fenced tables.** `executions`, `attempts`, `completion_claims`,
   `supervisor_status`, and `events` rows whose `principal` is `crucible`.
   `tasks` and `leases` are not fenced because the API writes tasks and the
   lease must be acquirable without a token; every supervisor transaction
   that touches a task also touches a fenced table, and the one that does
   not (attempt-lease renewal) verifies the lease explicitly. The token is set per transaction
   with `set_config(..., true)`.
7. **Provider handles and workspaces are re-derived from the attempt row**
   after a restart (`handle`, `workspace_path`). An attempt left in
   `launching` with a live provider handle is adopted (`attempt_adopted`).
8. **Fake provider behaviors are selected by the image tag**
   (`crucible-worker:fake-<behavior>[-<n>]`) so a contract alone drives the
   test; `FakeProvider.script()` overrides per external id. Behaviors:
   succeed, succeed-noreport, blocked, blocked-nofile, crash, environment,
   hang, vanish, prepare-fails.
9. **Only the `fake` provider is registered in C1**, so a contract naming
   `docker` is rejected at submit with the path named. `base_ref` existence on
   the remote and `WorkerImage` resolution are not checked (C3, C5).
10. **Policy validation uses the seeded document directly.** Migration 0001
    seeds `default-software` version 1 with the 05b defaults as data. C1
    checks `limits`, `retry.eligible_classes`, `git.work_branch_pattern`,
    `git.protected_branches`, `repository.required_checks`, and
    `images.allowlist`. PolicyV1 as a model and the policy API are C2.
11. **Tokens** are `cru_<principal ulid>.<secret>`; stored as a 16-byte salt
    plus SHA-256 of salt and secret; compared in constant time. The secret has
    256 bits of entropy, which is why a fast hash is acceptable.
    `crucible-admin token create` prints the token once; `--rotate` replaces
    an existing principal's token.
12. **Repositories** register through `crucible-admin repository register` or
    `PUT /v1/repositories/{name}` (admin). Registration needs no credential.
13. **Event kinds** are one per state change with `from` and `to` in the
    payload, enforced by a CHECK constraint the migration owns; a unit test
    keeps the constraint and the enum equal.
14. **Idempotency keys** live in an `idempotency_keys` table (not in the 14
    table list) keyed by principal and key with the request body hash and
    the stored response. Two concurrent first requests with the same key can
    both execute (see 25).
15. **Reconciliation is the tick.** The idempotence tests compare task,
    execution, attempt, event, claim, and contract rows; lease expiry times
    and the `supervisor_status` liveness row are expected to change.
16. **Logging** is the standard library with a JSON formatter; `task_id`,
    `execution_id`, `attempt_id` come from a context bound around each unit of
    supervisor work. Timestamps carry `+00:00`.
17. **Report handling.** A report that parses is stored as the claim; a report
    matching a secret pattern is stored as `{"redacted": true}` with the
    match path in `parse_errors`, and the attempt counts as
    `completed_without_report`. `blocked.md` text is stored in the
    `task_blocked` payload (redacted the same way); escalation and wake rows
    are C2. Provider `cleanup` is not called in C1 (`logs_drained` is C3).
18. **Problem types** are URNs, `urn:crucible:problem:<slug>`.
19. **`crucible serve --reload`** is accepted and logged as not implemented.
20. **`/ready` is unauthenticated** (04 marks only `/health` so). The compose
    healthcheck and Foundry's start-of-session probe need it without a token;
    it reveals the lease holder name and the migration revision, nothing else.
21. **Cancellation and partial reports.** A report present after a cancel
    drain is recorded in the `attempt_collected` payload
    (`partial_report_kept_unparsed`) and never parsed as a claim (16); it
    becomes an artifact in C3.
22. **Stranded launches.** An attempt still in `preparing` or `launching`
    with no provider handle when the observe step runs was orphaned by a
    crash mid-launch; it is classified `environment` and the retry rule
    applies. One with a live handle is adopted.
23. **Kill is repeated.** After the grace deadline the supervisor kills on
    every tick until the provider stops seeing the worker; `killed_at` on the
    attempt keeps the event single. Cancel kills write `attempt_cancel_kill`,
    timeouts `attempt_timeout_kill`.
24. **Lease holder names are per process** (`<configured or host>:<pid>:<suffix>`),
    and only an expired lease can be taken, whatever the holder name says; every
    acquisition bumps the token, so a same-named replacement never shares one. The
    trigger reads the lease row `FOR SHARE` so a write racing a takeover waits
    for the takeover to commit and then sees the new token. `supervisor_status`
    is a fenced table; attempt-lease renewals verify the supervisor lease in
    the same transaction.
25. **Idempotency keys are scoped by route path** in the request hash; a
    concurrent first request that loses the store race still returns its own
    result rather than a 500.
26. **Compose profiles.** `.env.example` sets `COMPOSE_PROFILES=full` so plain
    `docker compose up` starts everything and `--profile dev` (which overrides
    the variable) starts `postgres` only, matching 13. `migrate` is a one-shot
    service; `crucible` waits for it.

## Not in C1

Workers, heartbeats, checkout leases, log chunks, artifacts, evidence, gates,
wakes, escalations, policies API, amendments, corrections, Docker provider,
socket and egress proxies, GitHub anything.

## Proposed specification changes

- 09 side-effects table: task `start` cannot create the execution and first
  attempt in the API transaction while 14 fences those tables. Suggest:
  "start records the request; the supervisor creates the execution and first
  attempt on its next tick".
- 09 attempt diagram: `running --timeout--> exited` needs somewhere to hold
  the drain deadline; suggest naming `drain_deadline` and
  `termination_reason` on the attempt.
- 14: add `idempotency_keys` and `completion_claims` to the fenced or listed
  tables; state that `events` fencing is conditional on `principal =
  'crucible'`.
- 14: the fenced-token trigger must nest the `events` principal check, since
  PL/pgSQL compiles `NEW.principal` for every table it is attached to.
- 10: state that lease renewals and the liveness row are exempt from
  "reconciliation changes nothing the second time".
- 04: `POST /tasks/{id}/start` overrides create an amendment; until
  amendments exist the body must agree with the contract.
- 13: document that `COMPOSE_PROFILES=full` in `.env` is what makes both
  modes work with one compose file.
